# GS-005 — DIGIMON KNOWLEDGE STUDIO
## Inteligência de domínio, pesquisa dos jogos, Digimons, evolução e sistemas de gameplay

Você é o agente principal responsável por coordenar a implantação deste módulo no Game Studio OpenClaw.

Sua missão é criar uma base de conhecimento profunda sobre os jogos Digimon, transformando referências, gameplays, bancos de dados e informações técnicas em uma estrutura de dados utilizável no desenvolvimento do nosso MMORPG.

O objetivo não é criar uma enciclopédia isolada.

O objetivo é permitir que todos os agentes do Game Studio conheçam o universo Digimon e utilizem informações consistentes para desenvolver os sistemas do jogo.

# 1. CONTEXTO E IDENTIDADE DO PROJETO

Nosso jogo será um MMORPG 2D ambientado no universo Digimon.

Referências principais:

- IdleDex: estrutura de exploração, grid, mundo compartilhado e organização dos mapas.
- Drakantos: qualidade visual, personagens, animações, efeitos e acabamento.
- Digimon: criaturas, personagens, evolução, atributos, habilidades, treinamento, chefes e ambientação.

O conteúdo do jogo deve utilizar Digimons e elementos reconhecíveis da franquia.

Não criar monstros genéricos para substituir Digimons.

Não inventar informações oficiais.

Não misturar automaticamente as mecânicas de jogos diferentes.

# 5. SISTEMA DE EVOLUÇÃO — PRIORIDADE MÁXIMA

Este é um dos sistemas mais importantes do projeto.

É obrigatório estudar como cada Digimon evolui em cada jogo.

NÃO criar uma árvore evolutiva linear e genérica.

Cada Digimon pode possuir caminhos evolutivos diferentes, requisitos específicos, evoluções alternativas, ramificações, condições especiais e até regressões.

O agente deve compreender e documentar isso individualmente.

## 5.1 Cadastro individual de evolução

Para cada Digimon, identificar:

- Nome.
- Estágio atual.
- Pré-evoluções.
- Evoluções possíveis.
- Caminhos alternativos.
- Evoluções especiais.
- Requisitos de cada evolução.
- Nível mínimo.
- Atributos necessários.
- Status necessários.
- Itens exigidos.
- Condições de treinamento.
- Condições de personalidade.
- Vínculo ou afinidade.
- Requisitos de missões.
- Requisitos de desbloqueio.
- Restrições.
- Possibilidade de regressão.
- Jogo de origem da informação.

Não presumir que todos os requisitos existem em todos os jogos.

## 5.2 Árvore evolutiva visual

Criar uma visualização de grafo para cada linha evolutiva.

Exemplo conceitual:

Digimon inicial
├── Caminho A
│   ├── Evolução A1
│   └── Evolução A2
├── Caminho B
│   ├── Evolução B1
│   └── Evolução B2
└── Caminho C
    └── Evolução C1

O exemplo representa apenas uma estrutura de dados, não uma linha evolutiva oficial.

Cada conexão precisa registrar seus requisitos.

Permitir visualizar:
- Origem.
- Destino.
- Requisitos.
- Evoluções alternativas.
- Caminhos bloqueados.
- Evoluções disponíveis.

## 5.3 Comparação entre jogos

O mesmo Digimon pode ter regras diferentes em jogos diferentes.

Por isso, manter árvores evolutivas separadas por jogo.

Exemplo de estrutura:

- Greymon — Next Order.
- Greymon — Cyber Sleuth.
- Greymon — Digimon Masters Online.
- Greymon — Dawn & Dusk.

Não combinar os requisitos automaticamente.

Depois da coleta, apresentar uma proposta de árvore evolutiva unificada para nosso MMORPG.

## 5.4 Evolução no nosso MMORPG

Projetar um sistema próprio que preserve a identidade Digimon.

Avaliar:
- Evolução por estágio.
- Caminhos alternativos.
- Requisitos de atributos.
- Treinamento.
- Itens.
- Missões.
- Afinidade.
- Condições especiais.
- Evoluções raras.
- Evoluções temporárias, se adequadas.
- De-Digivolução.
- Desbloqueio de novos caminhos.

A evolução deve ser uma decisão significativa do jogador.

Não permitir que o sistema escolha arbitrariamente uma evolução quando houver mais de um caminho disponível.

Apresentar os caminhos possíveis e seus requisitos antes da confirmação.
